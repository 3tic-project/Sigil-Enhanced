# 当前书籍内置翻译

翻译作为原生 Agent 的内置功能使用。直接在 Agent 中描述目标，批量工具修改当前窗口打开的书，包含尚未保存的编辑。默认在原文之后添加译文；使用 Sigil 的保存或另存为保存 EPUB。

## 使用

1. 在 **应用程序设置 → 原生 Agent → 翻译** 配置翻译模型、思考程度、1–8 路并发（默认 4 路）、自动/固定批次目标、新译文段间距及校正模型。供应商、地址、凭据和模型目录复用 Agent；扫描和术语整理使用 Agent 模型，校正默认沿用翻译模型。
2. 在 Agent 中说明范围和目标，例如“把当前书翻译为简体中文，默认双语对照，先扫描整理术语，再翻译和校正，最后保存词表到 Misc”。也可要求仅试译选区、当前 XHTML 或书籍浏览器所选文件；选区扩展到完整阅读段落。
3. Agent 规划后调用原生批量工具。成功批次立即写回，完成后 Agent 自动接续，汇报实际扫描、翻译、校正和失败数量。查询进度时直接询问 Agent。
4. 在聊天中发送“暂停翻译”“继续翻译”“停止翻译”可直接控制队列，无需额外模型请求。暂停停止派发新批次，已发出的批次仍可完成；停止会取消请求并丢弃迟到结果，已写入的译文保留。Agent 的停止按钮也会停止后台翻译。
5. 可要求 Agent 查看或调整临时计划、记忆及术语，导入明确指定的书内 JSON 或外部词表。支持 `source/target` 和 Orion 的 `src/dst/info` 字段。未显式指定 `locked` 的人工译名默认锁定，模型不能覆盖。定向纠词和补缺通过批量工具完成。
6. 需要复用时，要求 Agent 将术语表保存到 Misc，加入当前书的实际 Misc 目录，重名自动编号；也可显式更新既有词表。之后正常保存 EPUB，即可在其他会话或下次打开时显式导入。

没有独立翻译面板或菜单入口。计划、记忆、临时词表、队列、缓存、范围和进度属于**当前 Agent 会话与当前书**。同一会话内结束回复或隐藏 Agent 不影响后台任务；新建会话立即取消旧任务、清空临时资料，旧工具引用、旧范围 ID 和迟到回包不能访问、写入或通知新会话。关闭窗口或更换书籍同样清空临时资料。

已经写进 Book 的译文和显式保存的 Misc 词表属于普通书籍内容，会话重置不会删除。新会话不会自动导入旧词表，需用户明确要求。模型连接和翻译偏好属于应用设置，继续跨会话共用。没有任务数据库、跨重启恢复或本地 NER。

## 双语与格式

阅读段落包含行内元素和 ruby 基底文字，读音另供模型参考，不逐 XML 节点翻译。原文、链接和 ID 保留；译文以转义后的纯文本写入，使用 `se-translation` 标记。重复执行会识别已有译文，避免重复插入；能够识别 Orion/Vela 常见译文标记。XHTML 目录译文添加在同一个链接内；按 OPF 标识导航资源，文件名不必包含 nav/toc。NCX 标签以“原文 / 译文”更新，保留层级、ID、顺序和跳转目标。

超长段按句界、必要时按词间空白拆成有序文本片段，原文和已有译文均保留完整内容。模型分批处理，全部片段成功后才合回一个译文节点；部分片段失败时不写半段。没有可用句界/词界的极端文本明确失败，不按 XML 节点拆分或截断。

全书默认“中文阅读”：复用 Sigil 横排转换和 CSS 修正，设置 LTR 翻页方向并补充响应式图片样式。SVG 保留原有图形和链接结构，固定版式页面沿用原生转换器的保留策略。局部范围默认保留原书格式，也可手动选择。完成后复用 Sigil XHTML 检查和校验结果面板。

单次写回使用现有书籍事务和修订号，首次修改创建 Sigil 检查点，不自动保存 EPUB。等待网络期间不占用书籍事务。写入前重新核对原文和既有译文，保护用户期间的编辑。

## Agent 工具

内置 `book-translation` skill 使用以下批量工具，仅在当前 Agent 会话内使用原生控制器：

| 工具 | 用途 |
| --- | --- |
| `translation.prepare` | 从当前 Book 准备范围、目标语言和译风 |
| `translation.run` | 异步启动扫描、聚合、翻译、校正和格式修正 |
| `translation.status` | 读取实际进度、问题位置和用量 |
| `translation.control` | 暂停、继续、停止、补缺 |
| `translation.context` | 分页读取或更新临时资料；更新使用 terms 数组、plan 对象或 memory 字符串，兼容旧 value 参数 |
| `translation.revise` | 根据术语调整或用户要求批量校正译文 |
| `translation.format` | 应用中文阅读或保留格式预设 |
| `translation.save_glossary` | 将词表保存到实际 Misc 目录 |

可直接要求 Agent “把当前书翻译为简体中文，双语对照”或“把这个名字统一为……并校正相关译文”。工具负责组批和写入，Agent 无需逐句生成源码补丁。`run` 返回表示已经启动；完成后，宿主向发起任务的同一聊天会话发送带实际计数的后台通知，Agent 接续汇报、有限补缺以及用户要求的词表保存。等待当前聊天请求结清后再接续；换书、换会话或停止 Agent 后不接续旧任务。后台跟进有次数上限，不循环重启全书。“暂停翻译”“继续翻译”“停止翻译”三个独立聊天指令可直接控制队列，无需额外模型请求。

## 请求与速度

默认翻译目标约 3000 个 Unicode 字符，上限 4500 字符或 128 段；扫描约 10000 字符，上限 15000 字符或 512 段；校正按原译合计约 6000 字符，上限 9000 字符或 96 对。短对话合批，末批平衡，保持段落完整和顺序。请求只带短系统提示、当前批次、命中词条、短记忆和少量邻文，不带主聊天历史或 Agent 工具定义。

请求前按模型上下文和输出空间检查载荷，过大批次缩小；输出截断和协议错误可拆批重试，缺少译文只补缺段。自动模式连续三批完整成功且输出余量足够时小幅增加目标，仍受 4500 字符/128 段和模型空间约束；异常减批，固定目标不主动增长。每批最多重试两次；限流降低并发并短暂退避，认证等永久错误停止当前执行。

会话内缓存包括成功结果、按当前资源内容签名复用的段落解析，以及命中词条集合。词表、译风、模型参数或请求内容变化时不会误用旧结果；长段尚未写回的片段会按新的资料重做。扫描结果保留按章短记忆，翻译按当前章节选择有界内容。显式别名可跨批连接，人工锁定译名优先；全名/昵称有不同明确译法时保留各自形式，不按同姓或子串强行认作一人。定向纠词覆盖旧别名和反向别名。

状态工具记录实际供应商 token 用量及本地缓存命中，未提供的用量标为未知，不估算费用。状态结果提供最近最多 512 次请求的 P50/P95 延迟、解析和词条缓存命中，以及当前批次目标。

图片中的文字暂不翻译，不做 OCR。复杂 SVG 和固定版式保持保守处理；图片宽度适配不等于将 SVG 展平成位图。翻译的语义质量取决于所选模型，小样本真实连接验证不代替整书评估。

## 验证

```sh
cmake --build cmake-build-debug --target Sigil translation_text_test translation_batch_test translation_controller_test agent_harness_test agent_prefix_cache_test agent_book_ops_test vertical_conversion_invariants_test -j 6
ctest --test-dir cmake-build-debug -R '^(translation_(text|batch|controller|benchmark|window_integration|agent_acceptance_smoke)|agent_(harness|prefix_cache|book_ops|provider_cancel|provider_catalog|dock|dock_contract)|vertical_conversion_invariants)$' --output-on-failure
```

测试包括 ruby/行内换行/目录/UTF-8 位置、XML 与链接保留、重复插入和人工修改冲突、组批与词条匹配、模型响应校验、缺段重试、暂停恢复和迟到结果、术语分批聚合，新建会话清理、旧工具/范围隔离、忽略取消的迟到回包、写回期间重置，以及既有 Agent/格式转换回归。

macOS 原生窗口测试使用合成 EPUB 和回环 HTTP 服务，通过真实模型适配器检查未保存正文、双语写回、格式、任意文件名的 OPF 导航和 NCX、词表 JSON MIME、导出并重新打开 EPUB、新窗口无临时任务、重复翻译无模型请求。从真实聊天入口调用 Agent 规划/工具，验证后台完成后自动接续并保存词表；同时检查独立面板/菜单已移除、应用设置保留、新建会话与停止操作不会接收旧翻译回包或后台通知。日常 CTest 不发送真实供应商请求，不修改私人书籍。

`translation_controller_test --benchmark` 执行目标字数 1500/3000/4500 × 并发 1/2/4/8 的本地模拟矩阵。显式加 `--live` 才会通过环境变量指定的供应商发送合成日文，默认只比较并发 1/4；`--workflow` 改为六段的扫描、聚合、翻译和校正验证。必填环境变量为 `SIGIL_TRANSLATION_BENCH_URL`、`SIGIL_TRANSLATION_BENCH_API_KEY`、`SIGIL_TRANSLATION_BENCH_MODEL`；可选 `SIGIL_TRANSLATION_BENCH_PROVIDER`、`SIGIL_TRANSLATION_BENCH_AGENT_MODEL`、`SIGIL_TRANSLATION_BENCH_CONTEXT` 和 `SIGIL_TRANSLATION_BENCH_REPORT`。凭据通过环境传入，不放进命令参数、EPUB 或报告。
