# 纵横排版转换与安全审计

本文说明 Sigil-Enhanced 内置“纵横排版转换”的操作方式、转换机制、安全边界，以及
2026 年 8 月完成的实现审计。该功能随 **2.8.1E8** 进入正式发布。

## 功能入口

“增强”菜单提供三个入口：

- “分析纵横排版...”只分析，不修改 EPUB；
- “将竖排书籍转换为横排...”把可安全处理的 `vertical-rl` 页面转换为横排；
- “将横排书籍转换为竖排...”把可安全处理的 `horizontal-tb` 页面转换为竖排。

建议先运行“分析纵横排版...”，在“验证结果”中检查每个文件的类型、实际方向和风险。
执行转换后，同一文件可在代码视图中撤销该文件的一步写回；整书恢复应使用转换前自动创建的
Checkpoint。

## 转换机制

转换分为分析、预检、Checkpoint 和写回四个阶段。

1. 分析 OPF、XHTML 和每个页面实际关联的 CSS，识别实际书写方向、固定版式、模板和风险。
2. 在内存中生成所有 XHTML 与 OPF 结果，并验证 XML、可见文本、链接、锚点、ruby、图片和
   链接元素等不变量。任一计划文件失败，整批均不写回。
3. 精确预检通过且确有修改时，创建恢复 Checkpoint。缺少合法 UUID 的 EPUB 会在隔离快照中
   准备 UUID，只有 Checkpoint 成功后才把同一 OPF 作为一步可撤销编辑提交。
4. 再次检查资源没有在分析后变化，然后每个变化资源只写回一次。

转换页面有两种实现方式：

- 经验证的 DPFJ/EBPAJ `.vrtl/.hltr` 模板可启用“识别模板的结构化转换”。插件只切换该页面
  根元素上的成对 class，不修改共享样式表；
- 其它页面使用兼容覆盖。在 XHTML 中加入带专用标记的局部 `<style>` 和根 class，原 CSS 与
  inline style 保持不变。反向转换会删除插件自己的覆盖。

模板识别按页面生效。即使整书包含 `.vrtl` 和 `.hltr`，只有当前页面通过 `<link>` 及递归
`@import` 真正关联到成对规则，并且页面根元素有对应 class 时，才会切换 class。带查询参数、
fragment、百分号编码的书内路径均会解析；远程 URI、越界路径、循环导入和不存在的文件不会被
当成书内样式表。

## OPF 翻页方向

整书转换可同步 `spine` 的 `page-progression-direction`：竖排转横排使用 `ltr`，横排转竖排
使用 `rtl`。插件会在 OPF 中记录转换前的精确状态，因此反向转换能够恢复 `rtl`、`ltr`、
`default`，也能恢复为原先完全没有该属性的状态。

以下情况不会自动修改整书翻页方向：

- 只转换部分文件；
- 书中包含局部固定版式 itemref；
- OPF 的原值非法；
- 上次转换后翻页方向被人工修改。

插件记录与当前值冲突时会停止，不覆盖人工修改。

## 自动跳过与人工复核

以下内容默认不自动重排：

- 整书或局部 `pre-paginated` 固定版式，包括 EPUB 3 refinement 与常见 EPUB 2
  `fixed-layout` metadata；
- 带固定 viewport 的页面、图片页、含文本的 SVG 页面；
- 脚本与绝对定位共同控制的布局；
- 纵横方向信号冲突，或共享 CSS 有成对规则但页面没有明确根布局 class；
- 关联 CSS 或页内 `<style>` 解析失败；
- 源方向的 inline `writing-mode: ... !important` 会压过转换覆盖；
- 转换来源标记存在，但对应 class 已被人工修改。

普通 inline writing-mode 不会在整页自动转换中被重写。这样才能区分原本的局部横排表格、
局部竖排文字与页面根流，避免多次互转后把局部子流永久改错。

## 审计修复摘要

本轮审计修复了以下问题：

- 停止在整书流程中改写共享 CSS，避免删除 `text-orientation`、`text-combine`、`vert/vrt2`
  后无法反向恢复；
- CSS 模板从整书级猜测改为逐页验证，并支持 namespaced `<link>`、编码路径和递归 `@import`；
- OPF 翻页方向由简单互换改为记录来源并精确恢复，部分文件和混合固定版式不再改动全局方向；
- 正确读取 itemref `properties`、`rendition:layout` refinement 和 legacy fixed-layout metadata；
- 格式化缩进不再被当成图片页可见文本，普通章节内的 HTML `<nav>` 不再误判为 EPUB 导航页；
- 插件只删除带专用属性或与旧版生成内容精确相同的覆盖 `<style>`，不会删除碰巧提到插件
  class 名称的用户 CSS；
- 自动整页转换不再改写 inline style，并保护转换后的人工 class/OPF 修改；
- 转换计划或 OPF 变换任一失败会在写回前终止整批；Checkpoint 只在精确预检成功后创建；
- 修复 `! IMPORTANT` 大小写与空格识别，以及只移除已启用的 OpenType `vert/vrt2`，保留
  `"vert" 0`、`"vrt2" off` 和其它字体特性；
- 支持带命名空间前缀的 XHTML/OPF，避免新建无前缀 `<style>` 破坏文档命名空间；
- 含文本的 SVG 在两个转换方向都默认跳过。

## 验证范围

自动测试覆盖布局分析、模板识别、样式表依赖解析、XHTML/CSS/OPF 纯变换、内容不变量、
Checkpoint UUID 修复、编排事务契约，以及简体中文、繁体中文和日文翻译完整性。

真实书籍只读审计覆盖 7 本 EPUB，共 218 个 spine 页面。可自动处理的 146 个页面完成
“转换、反向恢复、再次转换、再次恢复”循环：146 个页面的可见文本、链接、锚点、ruby 与图片
语义保持一致，第二次循环结果稳定；7 个 OPF 的翻页方向往返均逐字节恢复。其余固定版式、
图片页、导航页或高风险页面按策略跳过。3 本缺少合法 UUID 的 EPUB 均通过 Checkpoint UUID
准备测试。

## 当前边界

- 本功能只处理可重排 EPUB 的布局方向，不负责把固定版式重新设计为流式版式；
- 兼容覆盖改变阅读器中的排版效果，但不会推断和交换未知模板的物理 margin、padding、尺寸或
  绝对坐标；这类视觉细节应人工核对；
- XHTML 有实质修改时会由 XML DOM 重新序列化，源文件的空白、引号或实体写法可能规范化；
  内容不变量会校验语义，多次互转不会继续累积格式漂移，但不承诺 XHTML 字节级恢复；
- OPF 翻页方向的插件变换承诺反向转换后恢复原文本；如果用户在中间人工改动受跟踪属性，插件
  会拒绝覆盖。
