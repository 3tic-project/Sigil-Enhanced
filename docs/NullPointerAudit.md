# 空指针与资源生命周期检查

基于 `d6dec4d34`，检查图书浏览器操作、搜索替换、编辑页延迟初始化、简繁转换弹窗及资源销毁后的回调。使用真实应用对象复现问题，再修复并测试。搜索栏布局保持在编辑器下方。

修复提交为 `bf991cc1a`。前一阶段见[锁与重入检查](LockAudit.md)，反馈来源、源码提交索引及 Windows 10 待测项目见[Windows E14 反馈修复](WindowsE14FeedbackFixes.md)。本页 17 个场景属于一个 CTest 集成测试；下方 20 项相关检查包含该测试，按最终复测结果汇总。

## 修复

| 路径 | 问题与处理 |
| --- | --- |
| XHTML/CSS 添加副本 | 原来只判断“存在当前资源”，没有检查转换后的资源类型；选中 CSS 等资源触发 XHTML 副本快捷键会崩溃。先确认类型，再创建副本，避免遗留空文件或部分修改 manifest |
| 字体混淆操作 | 对非字体选择直接使用转换结果，Debug 会断言退出，Release 可能解引用空指针。操作入口使用字体选择过滤；字体菜单勾选状态、封面图片菜单也检查实际目标类型 |
| 普通与增强搜索 | 全部编辑页关闭后，全书统计/替换仍直接保存“当前编辑页”。现允许没有编辑页的全书操作；当前文件范围返回空结果。增强搜索从所选范围首尾文件开始，不再读取空的当前资源类型；搜索目标列表不包含空资源 |
| 增强搜索正则转义 | 没有搜索输入框取得焦点时，目标组合框为空。检查目标及其行编辑器后再处理 |
| 等待资源加载 | 循环每次重新读取当前编辑页，处理事件时关闭或切换编辑页会导致空指针或等待错误目标。改为跟踪最初打开的编辑页，编辑页关闭或资源失效后结束等待；空资源直接返回 |
| 简繁转换 | 弹窗、预览或检查点创建期间，原编辑页、资源或书籍可能已经变化。以 `QPointer` 跟踪编辑页和资源，在返回后检查目标是否仍然有效；批量目标同样受保护。保留正常的文件、SVG 和选区转换 |
| 资源销毁后的编辑页 | 编辑页原来保留资源裸指针，删除后的元数据查询及已排队的初始化可能继续访问失效对象。改为 `QPointer`，资源实际销毁后返回空元数据；同时处理 `Deleted` 和直接的 QObject 销毁通知，避免重复关闭。XHTML 和通用文本编辑页在资源失效后跳过初始化、保存和相关刷新 |

保留构造阶段非空的对象约定，检查集中在类型转换、可选当前编辑页和跨事件循环的生命周期边界，没有给所有指针机械添加空判断。

## 复现与静态检查

- 修复前，错误类型的 XHTML 副本、关闭全部编辑页后的普通搜索、等待加载时关闭编辑页，均在独立测试进程中出现 `SIGSEGV`。
- 错误类型的字体操作触发 `font_resource` 断言并以 `SIGABRT` 退出。
- 增强搜索复测进一步暴露空当前资源；LLDB 确认崩溃位于 `FindReplacePlus::GetNextContainingResource` 的资源类型读取。
- 旧资源生命周期测试中，资源删除后仍可获得原来的裸指针。测试区分删除通知和 Qt 延迟析构，先完成实际析构，再验证元数据、已排队初始化和保存调用。
- 简繁转换测试在选项或预览期间关闭原编辑页，确认返回失败且不写入；旧选项场景出现超时，不将它记为已证实的崩溃。
- 用应用真实编译参数运行 Apple Clang Static Analyzer，检查图书浏览器、主窗口扩展、FlowTab、ContentTab、TextTab 及两种搜索实现。主窗口扩展的两处潜在空调用和增强搜索转义目标的空调用已处理；剩余未使用赋值提示与本轮空指针问题无关。Qt 父对象管理和 `deleteLater` 也可能产生分析器无法理解的所有权提示，按实际对象生命周期核对。

另外检查了预览测量回调的 `QPointer` 保护、带 QObject 上下文的定时回调，以及 Agent 运行中关闭窗口时的取消和延迟关闭路径。这些已有保护继续保留。

## 回归测试

新增 `null_pointer_integration`，使用隔离设置和临时 EPUB，包含 17 个独立进程场景：

- 错误类型的 XHTML/CSS 副本；错误类型字体操作及有效字体混淆/解除混淆。
- 两种搜索模式在没有编辑页时全书统计、全书替换及当前文件空结果；增强搜索另外覆盖无输入框焦点的转义操作。
- 加载等待期间关闭目标编辑页，以及空资源调用。
- 转换选项、转换预览期间关闭原编辑页。
- 正常 XHTML、SVG、带预览的选区简繁转换。
- XHTML/CSS 编辑页分别在未初始化、已加载时销毁所属书籍；另覆盖资源直接析构。验证单次关闭通知、空元数据、已排队回调及保存调用。

```sh
cmake --build cmake-build-debug --target Sigil
ctest --test-dir cmake-build-debug -R '^null_pointer_integration$' --output-on-failure
# 只复测一个场景：
python3 tests/run_null_pointer_integration.py cmake-build-debug --scenario search-plus
```

真实对象测试当前使用 macOS Ninja Debug 构建。Windows 10 实机行为仍需复测；本记录不将第三方库内部的全部指针路径视为已经验证。
