# 内置翻译验证记录

历史验证始于 2026-11-14；最新的 Agent 专用入口及会话隔离验证见文末。使用合成 EPUB 和原创日文短场景；未发送私人书籍，未记录 API Key 或端点地址。

## 2026-11-14：本地验证（当时含独立面板）

最终主程序构建成功，13/13 项 CTest 通过（23.68 秒）。独立窗口流程处理 224 个阅读段落；另一个窗口从聊天入口启动并由 Agent 完成词表收尾。

回归覆盖段落/ruby/UTF-8、长段分片及整段合回、NCX 和 XHTML 导航、显式别名与全名/昵称不同译法、锁定词条、按别名纠词、暂停/继续/停止、人工修改保护、缓存失效、Agent 校正模型选择及既有 Agent/方向转换。

原生窗口测试从两个入口分别推进：独立翻译面板；真实聊天入口经 Agent 规划与工具调用启动，再由后台完成通知接续保存词表。模型响应由回环 HTTP 服务模拟，资源层、窗口、模型适配器和 Agent 循环均使用真实实现。验证导出的 EPUB、JSON MIME、重新打开词表和临时状态清理。

速度矩阵使用 600 个合成段落、每次模拟请求 15 ms 固定等待，比较 1500/3000/4500 字符目标和并发 1/2/4/8 共 12 组。该测试验证完整率和批处理行为，不能用模拟耗时预测真实供应商吞吐。

## 真实连接小样本

复用本机 Sigil 已配置的 Agent 连接，翻译模型为 `deepseek-v4.1-flash`。只翻译六个原创日文段落重复组成的 180 段测试文本；固定目标 3000 字符。关闭可控的翻译思考开关，使用两条锁定人名映射。

| 并发设置 | 总耗时 | 请求数 | 成功段落 | 缺段/重试 | 指定人名命中 | 输入/输出 token | 缓存输入 token |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 76.09 秒 | 2 | 180/180 | 0/0 | 210/210 | 8140/6823 | 3456 |
| 4 | 38.19 秒 | 2 | 180/180 | 0/0 | 210/210 | 8140/6518 | 3456 |

这是各一次的两批小样本；设置并发 4 时实际最多只有两条请求。重复段落、供应商缓存、生成差异和服务负载都会影响耗时，不能将接近两倍的差值外推到整书或八路并发。

另外执行了六段不重复原文的真实流程：扫描 → 聚合 → 翻译 → 校正。45.00 秒，4 次请求，6/6 已扫描、6/6 已译、6/6 已校正，零失败、零重试；指定人名命中 7/7，供应商报告输入/输出 2372/2468 token。

逐段检查这六条样例，未见明显漏译和人物译名不一致。例如：

> ミナは窓の外を見た。「リク、雨が止んだら、約束の場所へ行こう。」
>
> 米娜望向窗外。「陆，等雨停了，我们就去约定之地吧。」

> リクは頷いた。彼がポケットから取り出したのは、昨日ミナが渡した小さな鍵だった。
>
> 陆点了点头。他从口袋里取出的，是昨天米娜交给他的那把小小的钥匙。

自动报告保留 `semantic_quality_evaluated=false`，因为完整率和术语命中不等于自动判定语义正确。这轮小样本不覆盖整书长距离指代、多角色同姓歧义、复杂脚注或出版级文字润色。

## 2026-11-15：真实 Agent 自主规划与收尾

主程序构建成功，14/14 项本地回归通过（26.89 秒）。

已从真实聊天入口使用既有模型连接完成两组自然语言验收，不预设工具调用序列：

- 正常组：扫描/汇总/翻译/校正完成后保存词表；追加指令将人物译名改为美奈。初始 12/12 已译及校正，追加定向校正 4 段、四处美奈和三处陆正确，无关译文保持，词表只有一份并原地更新。耗时 177.84 秒，主 Agent 17 次请求、翻译子请求 5 次，两次后台完成通知。
- 故障组：连续注入三次 503 错误结果耗尽原生内部重试，真实 Agent 自主选择一次补缺并等待新的完成通知。最终扫描/翻译/校正均 12/12、失败 0，整本只扫描一次；原始 EPUB 未保存。耗时 140.01 秒，主 Agent 10 次请求、实际翻译子请求 4 次，两次后台完成通知。

验收发现并修正了临时上下文参数类型不明确、改名绕用正则、阶段列表遗漏/误名，以及补缺启动后反复查询状态的问题；另为主模型零输出的连接关闭/重置增加一次保守重试，保留鉴权错误、已有输出及取消行为。

复跑方式、脱敏报告和合成 EPUB 输出说明见 [真实 Agent 翻译验收](TranslationLiveAgentAcceptance.md)。本轮是单模型、小型合成书的功能验收；真实 LLM 自主规划仍未进行大样本或多供应商评价。

## 2026-11-15：收敛为 Agent 内置功能与会话隔离

分支 `refactor/agent-only-translation`。删除独立 TranslationPanel、增强菜单和视图入口；翻译配置继续集中在应用程序设置的原生 Agent 区域。PRD、工具说明和内置 skill 已同步为 Agent 入口。

临时范围、语言/译风、计划、记忆、词表、队列、缓存及进度绑定当前 Agent 会话。新建会话立即取消旧请求并清空状态，旧工具引用和旧范围 ID 拒绝访问；忽略取消的旧请求回包不能写入、覆盖资料或发送新会话通知。测试也覆盖写回信号期间重置会话，避免继续使用已清空的段落索引。Book 中已写入的译文与显式保存的 Misc 词表保留，新会话不自动导入。

主程序构建成功，14/14 项 CTest 通过（29.38 秒）。原生窗口从 Agent 入口以 7 次回环 HTTP 模拟请求完成 224 个阅读单元的扫描、翻译、校正与格式整理，再由后台通知接续保存词表。验证独立 UI 不存在、应用设置读写、实际点击 New Session/Stop、取消后迟到回包、无旧会话通知，以及导出重开后的 JSON MIME 与双语正文。

Agent 回复结束后，只要后台翻译仍在执行或暂停，既有 Stop 按钮保持可用；不锁住聊天、新会话或模式选择。后台结束不会干扰仍在执行的主 Agent 停止操作。此轮使用离线/回环模型，不新增真实供应商请求；此前真实模型验收保留为历史记录。

新增验证包括：

- 主 Agent／批次前五次断网后第六次请求成功，连续失败最多六次；退避中停止不发新请求，事件记录重试序号、上限和等待。
- 原生 HTTP 的连接关闭、429 与 Retry-After、401、不出首 token、200 后流中断；检测已流出的内容，避免主 Agent 重放部分答案。模拟请求使用非敏感凭据。
- 现有 Agent 面板中的任务卡展示阶段及独立扫描／写入／校正计数；实际点击暂停、继续、新建会话和停止，验证无旧回包／任务数据跨会话。
- 准备三段后只翻译其中一段，空阶段、空列表和越界明确拒绝；补缺不会扩到范围外；扫描失败后保留成功译文，只补扫描／聚合。
- 输出截断后缩小输入并增加输出预留；分阶段错误不会被后续成功的翻译擦掉；自身格式变化后可继续校正，失败重译保留旧译文且能补重译。
- 调试导出包含当前会话后台任务及有界子请求诊断，继续对错误和任务摘要做密钥脱敏；普通状态回执不夹带完整诊断历史。
