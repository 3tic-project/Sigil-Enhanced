# 保持阅读顺序的目录层级编辑

Sigil-Enhanced 的“编辑目录”可以在不改变目录先序阅读次序的前提下提升或降级条目。
这里调整的是 Nav/NCX 的父子关系，不会改写正文中的 `h1`–`h6` 标签。

## 提升与降级

左箭头“提升一级”默认采用保持阅读顺序的规则。假设 A 的子目录依次为
`B, C, D, E, F`，选择 C 和 E 后提升：

- C、E 都成为 A 的同级条目，而不是互相嵌套；
- C 接管 C 与 E 之间的 D，并将 D 追加在 C 的既有子目录之后；
- E 接管其后的 F；
- B 仍留在 A 下；所有条目的先序次序保持不变。

若同时选择父项和后代，只处理最高的已选祖先。跨父项选择会基于操作前的同一快照
统一规划；只要其中包含顶层条目或计划重叠，整次操作都不执行。

右箭头“降级一级”把每个连续选择区段移到其前一个未选同级条目之下，并追加在该项
已有子目录之后。没有前驱的区段会让整次操作失败。上、下箭头仍只调整同级顺序，
因此可能有意改变阅读次序。

“提升时接管后续同级条目”默认开启并记入本机偏好设置。关闭后，提升使用旧行为：
后续同级条目留在原父项下，此时先序次序可能改变。

## 撤销、取消与写回

对话框使用独立的撤销栈。提升、降级、同级移动、增删、标题和目标编辑都支持
Ctrl/Command+Z 及平台对应的重做组合键；标题输入框有焦点时，快捷键优先撤销输入框
内尚未提交的文字，不会误触发目录级撤销。

取消会丢弃对话框内所有编辑，不修改 Book。确定时只提交最终差异；如果打开后没有
变化，不会重写导航资源，主窗口也不会把 Book 标记为已修改。操作后尽量保持稳定
选区、展开状态和滚动位置；当新结构使滚动范围缩小时，位置会收敛到新的有效上限。

EPUB 3 默认只更新 Nav。若书中还带有兼容 NCX，对话框会明确提示，并显示“同时同步
兼容 NCX”选项；该选项每次打开默认关闭，避免无意改写第二套导航。EPUB 2 直接更新
NCX，不显示此选项。

纯层级操作会重挂原有 Nav `<li>` 或 NCX `<navPoint>` 节点，保留节点 id、属性、
内联标记、标签、目标和非目录区域。NCX 的 `head`、`docTitle`、`docAuthor`、
`pageList` 等外围内容不因目录层级写回而重建。若用户实际增删条目或改动标签/目标，
无法安全一一映射的新目录区会使用现有生成器重建，但 Nav 的包装、标题及其他 nav，
以及 NCX 的 `navMap` 外围内容仍会保留。

EPUB 3 缺少 Nav 时，主窗口会先进入现有的“生成导航文档”预览与确认流程；取消预览
不会创建资源，确认后才进入目录编辑。

## Native Agent

内置 Agent 可用 `toc.inspect_hierarchy`、`toc.plan_transform` 和
`toc.apply_transform` 调用同一个 `TocTreeTransform` 与原节点重挂器。它以稳定节点
ID 规划提升/降级，绑定 controller 会话、书籍修订和 Nav/NCX 精确源码；apply 只创建
独占暂存事务，仍须 `transaction.preview` 和 `transaction.commit`。

该流程只改变导航层级，不编辑 XHTML `h1`–`h6`，也不增删目录项或修改标题/目标。
EPUB 3 双导航书籍默认只改主 Nav，不自动同步兼容 NCX。协议、错误和验证边界见
[Native Agent 原生目录层级工具](AgentNativeTocTools.md)。

## 工程与性能

核心规则位于 `TocTreeTransform`，只处理稳定节点 ID、`parentId`、有序孩子、标签和
目标，不依赖 `QStandardItem` 行号。每次操作先生成完整计划并验证节点集合、单一父项、
无环、元数据不变与先序约束，再一次更新视图。显式旧提升模式会明确跳过先序不变约束。

超过 1,000 项的目录初始只展开顶层，不逐项调用 `expandAll`。macOS 15.7.7、Qt 6.7.3、
AppleClang 17、Ninja Debug 的合成测量为：纯变换 1,000 项 P95 约 6 ms，10,000 项约
56 ms；真实 EditTOC 的 10,000 项提升（含模型重建和视图状态恢复）为 150 ms，低于
300 ms 目标。该数字不是 Windows/Linux Release 构建或真实出版物的替代证据。

## 测试

```sh
cmake --build build --target Sigil toc_tree_transform_test -j 4
ctest --test-dir build --output-on-failure \
  -R '^(toc_tree_transform|edit_toc_hierarchy_integration)$'
```

纯测试覆盖单项/多项提升、连续和不连续区段、嵌套与跨父项选择、边界原子失败、旧模式、
降级、重复标签不同目标、不变量与 1,000/10,000 项预算。macOS 原生集成测试链接真实
应用对象，覆盖 EditTOC 控件、快捷键焦点、完整本地撤销、设置、取消/无变化确定、
EPUB 2 NCX、EPUB 3 Nav、双导航显式同步、外围源码与节点 identity 保留，以及真实
10,000 项视图路径。

当前自动化未替代 Windows/Linux 原生主题、屏幕阅读器、真实大型 EPUB、EPUBCheck、
独立阅读器和进程终止/断电级事务测试。
