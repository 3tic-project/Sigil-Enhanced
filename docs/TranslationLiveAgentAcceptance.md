# 真实 Agent 翻译自主执行验收

使用真实 MainWindow、聊天入口、Agent 循环、原生翻译控制器和本机已配置的模型连接。测试发送自然语言任务，不预设工具调用序列，不替模型生成计划、术语或译文。

翻译现仅通过 Agent 使用，设置位于应用程序设置的原生 Agent 区域。临时资料按会话隔离；新建会话会取消旧任务并清空范围、计划、记忆、词表及缓存，书籍内容保留。无需独立翻译面板。

合成 EPUB 含两个章节、ruby、脚注及目录，共 12 个阅读单元。只读取既有 Sigil 配置的 Agent 区域并复制到隔离的临时设置；原配置保持只读，测试前后核对文件摘要。报告不包含密钥、端点或模型内部思考内容。

## 验收场景

1. **正常执行与后续纠词**：要求先给简短计划，扫描全文、汇总术语、翻译和校正，保留原书格式，最后保存词表并报告数量和未保存状态。随后只以自然语言要求修改一个人物译名，更新原词表，保留其他译文。
2. **失败后自主接续**：在首个翻译批次连续注入三个 503 错误结果，耗尽控制器的两次内部重试。规划 Agent 仍使用真实模型；观察它如何根据后台失败结果选择补缺，复用扫描结果，完成校正和词表保存。

检查实际状态和导出 EPUB：扫描/翻译/校正覆盖全部单元，人物译名与词表一致，只有一份词表，纠词不改无关段落，原文 ID/链接保留，原始 EPUB 文件未被 Agent 保存。完整任务必须实际选择 scan、aggregate、translate、review；接受默认工作流或显式完整阶段。计划可以在只读扫描期间展示，必须早于译文写回，不要求固定的工具先后顺序。

失败接续可以使用 `retry_failed`，也可以在同一上下文只重跑缺失译文和校正；不接受重新扫描全书或逐句源码补丁。注入故障是受控测试条件，并非供应商真实宕机。

## 本轮发现与修正

- 原 `translation.context.value` 未声明类型，真实模型反复将术语数组编码为字符串而被拒绝。工具增加明确的 `terms` 数组、`plan` 对象和 `memory` 字符串；兼容完整 JSON 字符串，损坏 JSON 仍明确拒绝。`revise.terms` 同时补上词条结构说明。
- 后续改名曾绕用正则编辑。系统提示与 skill 明确采用 `translation.revise`，并用已有资源 ID 更新词表；原生翻译工具自行管理事务。
- 模型自选阶段曾遗漏 aggregate，或写成不存在的 glossary 阶段。工具列出合法阶段，完整任务明确默认不传 stages；preserve 只改变格式预设。
- 补缺或纠词启动后，模型曾反复查询状态。工具和完成通知明确这两者同样异步执行；应结束当前回复，等待下一条宿主完成通知。
- 真实连接曾在首个输出前关闭。Agent 对零输出的 connection closed/reset 只自动重试一次；已输出内容、鉴权错误、普通 HTTP 错误和取消不走这条重试，避免重复执行工具。

## 复跑

先构建 `Sigil`。不收费的测试用于检查验收脚本与窗口集成，不作为真实自主规划的结果：

```sh
python3 tests/run_translation_live_agent_acceptance.py cmake-build-debug --smoke
```

真实调用必须显式指定 `--live`，会使用所选 Agent 连接发送合成原文：

```sh
python3 tests/run_translation_live_agent_acceptance.py cmake-build-debug --live \
  --output cmake-build-debug/translation-live-agent-acceptance/latest
```

可用 `--settings` 指定既有 Sigil INI，或以 `--case normal` / `--case recovery` 单独复跑。密钥不放在命令参数中。输出目录包含脱敏的逐事件 JSON、实际调用和用量、样例译文以及验证后的合成 EPUB。

## 2026-11-15 实测结果

规划与翻译均使用既有连接的 `deepseek-v4.1-flash`。最终候选版本两组均通过，参数/工具执行无错误，无正则或逐句源码改写；原始配置及 EPUB 文件未改变，导出的原文 ID、目录及脚注链接保持。主程序构建成功，14/14 项本地回归通过（26.89 秒）。

| 场景 | 耗时 | 主 Agent 请求 | 翻译子请求 | 后台完成通知 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 正常翻译＋自然语言改名 | 177.84 秒 | 17 | 5 | 2 | 初始 12/12 已译及校正；追加校正 4 段，四处美奈、三处陆正确，同一词表原地更新，无关译文不变 |
| 三次注入错误后自主补缺 | 140.01 秒 | 10 | 4 | 2 | Agent 自主选择一次 retry_failed；最终扫描/翻译/校正均 12/12，失败 0，未重扫全书 |

翻译子请求数只计真正发送给供应商的调用，不含三次注入错误。两组各只启动一次完整扫描流程；后续分别为定向校正和补缺，未用新的用户“继续”消息驱动后台收尾。

这是单模型、小型合成书的功能验收，不等于整书翻译质量或多供应商稳定性评估。请求与用量完整记录在输出 JSON；模型内部思考正文未记录。整体测试范围见 [翻译验证记录](BuiltinTranslation-Validation.md)。
