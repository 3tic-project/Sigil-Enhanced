# 搜索历史与窗口启动

## 查找与替换

普通搜索和增强搜索各自保留下拉历史，增强模式也保留预搜索历史。
**新开窗口或新启动的实例，查找、替换、预搜索输入框都为空**，不会默认选择任何历史项。

- 用户可以从下拉列表主动选用旧项；执行查找或替换后更新历史，同一内容不重复添加。
- 未执行的草稿不保存为下次启动的输入；旧版单独保存的当前输入记录会清理。
- 当前窗口内连续操作、收起再打开面板或切换搜索模式，保留该窗口正在使用的内容。
- 确认“清空查找替换历史”后立即保存清空结果。
- 关闭没有改过历史的旧窗口，不会覆盖另一窗口较新的历史。

历史沿用原有条数限制；手动保存的命名搜索方案仍可主动加载。

## 多实例配置访问

主配置 `sigil_v6.ini` 与增强配置 `sigil_extend.ini` 使用 QSettings 的 INI 后端。
这些对象不长期持有配置文件句柄；读写时使用 Qt 的临时文件和进程间锁，保持原子同步开启。
文件不可写或被外部程序以不允许写入/替换的方式占用时，通过 `QSettings::AccessError`
报告失败。锁暂时被其他写入者占用时可能等待，不应据此把界面等待当成进程崩溃。
参见 [Qt 多进程配置访问](https://doc.qt.io/qt-6.10/qsettings.html#accessing-settings-from-multiple-threads-or-processes-simultaneously)。

本轮还修复了设置中切换普通/增强搜索模式后旧编辑器指针未清空的问题，避免关闭窗口时
重复释放搜索编辑器。该对象生命周期问题已在实际 MainWindow 集成测试中复现。

## Windows 启动与标题栏

Qt 的真正全屏模式会隐藏标题栏等窗口装饰；它与保留标题栏、使用桌面工作区的最大化
不同。参见 [Qt QWidget 全屏说明](https://doc.qt.io/qt-6.10/qwidget.html#fullScreen-prop)。

Windows 在没有有效已保存状态，或关闭“记住上次窗口位置、状态和大小”时，默认最大化。
窗口交给 Windows/Qt 处理工作区、任务栏和屏幕缩放，不按屏幕像素手动拼出一个窗口矩形。
其他系统继续默认全屏。

旧版 Windows 自动全屏记录首次恢复时迁移为最大化，保留标题栏；普通窗口、最大化和面板
布局继续恢复。迁移后，如果用户明确进入全屏并保存该状态，之后仍按全屏恢复。
关闭布局记忆时不会覆盖已有布局。

正常窗口的位置和尺寸仍通过 `saveGeometry`/`restoreGeometry` 恢复；Qt 会检查越出屏幕的
旧坐标并调整到可用区域，避免拔掉显示器后沿用屏幕外的位置。参见
[Qt 窗口位置恢复说明](https://doc.qt.io/qt-6.10/restoring-geometry.html)。

## 验证

- `search_memory_integration` 使用实际 MainWindow 和两种搜索控件，在独立进程之间验证
  历史保留、启动时输入为空、草稿不自动恢复、模式切换、退出、多窗口及清空。
- `settings_concurrency` 使用与 Sigil 相同的 QSettings INI 后端，验证长时间存活的配置对象、
  文件监视器、并发读写、短期锁竞争和写入失败恢复。Windows 分支额外使用原生
  `CreateFileW` 测试独占访问与共享冲突，确认已有配置不会被失败的写入破坏。
- `window_startup_policy` 覆盖 Windows/其他平台的新配置、已记忆状态、旧全屏迁移与
  后续明确保存的全屏，并检查最大化窗口仍有标题栏标志。
- `main_window_layout_integration` 验证窗口和面板恢复，以及旧坐标在屏幕外、尺寸大于
  当前屏幕时标题区域仍可访问。

本机使用 macOS 与 Qt offscreen 平台运行这些测试；Windows 分支的状态选择可在本机验证，
真实 Windows 桌面的不同 DPI、多显示器与任务栏位置仍需在对应环境验收。
