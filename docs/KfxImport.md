## 2. 产品摘要

本功能将无 DRM 的 Amazon KFX 文件转换为可在 Sigil-Enhanced 中继续编辑的 EPUB 3，并把转换能力接入两个用户入口：

1. “增强”菜单中的 `KFX 转换…`；
2. 向 Sigil-Enhanced 窗口拖入 `.kfx` 或 `.kfx-zip` 文件。

菜单转换完成后，用户可以选择：

- 将结果另存为指定的 EPUB 文件，但不影响当前窗口；
- 将结果作为一个尚未保存的新文档在新窗口打开。

拖放 KFX 时必须先提示用户，默认操作为“转换并在新窗口打开”，不得把 KFX 当作普通资源加入当前 EPUB，也不得静默转换。

本需求同时调整 Sigil-Enhanced 的默认保存行为：默认不添加或更新 `Sigil version` 元数据。对于一本成功加载、未发生任何编辑或自动修复的 EPUB，普通“保存”必须成为真正的 no-op；“另存为”和“保存副本”必须直接复制原始 EPUB。由此保证未修改 EPUB 在打开再保存后不被写入额外内容，并在可满足条件时保持整个文件字节级一致。

## 3. 背景与问题

### 3.1 当前用户问题

- Sigil-Enhanced 只能直接打开 EPUB、HTML 和文本，KFX 需切换外部工具转换；
- 外部脚本的输入、输出目录和命名规则与编辑器割裂，转换后仍需手工定位并重新打开 EPUB；
- 当前拖放逻辑只特别识别 EPUB，KFX 会落入“添加已有文件”路径，容易被错误加入当前书籍；
- 当前 EPUB 导出器默认写入或更新 `<meta name="Sigil version" ...>`，即使用户未编辑书籍也会改变 OPF；
- EPUB 3 导出还会无条件更新 `dcterms:modified`，因此仅关闭 `Sigil version` 仍不足以兑现“未修改保存不变”；
- 普通重新打包还会改变 ZIP 项顺序、时间戳或压缩结果，只有未修改时跳过导出或直接复制原文件，才能提供可验证的不变性。

### 3.2 产品机会

Sigil-Enhanced 已具备多窗口、EPUB 导入、原子保存、内置 Python、`lxml`、Pillow、校验结果和内置插件模块。将 KFX 转换作为受控导入工作流接入，可以统一完成：

- 输入预检与 DRM 拒绝；
- KFX/KFX-ZIP 到 EPUB 3 的转换；
- 转换结果校验；
- 另存为或新窗口打开；
- 清晰的错误分类、进度、取消与临时文件清理；
- 未修改 EPUB 的无损保存语义。

## 4. 参考实现审计与技术选型

### 4.1 参考实现对比

| 实现 | 优点 | 当前缺口或风险 | 首版定位 |
| --- | --- | --- | --- |
| `kfx2epub` Python，提交 `a5530a923bf74dd53af5a64c9f50aecbbff90ef6` | 直接支持 `.kfx` 与 `.kfx-zip`；已有日本竖排、Ruby、固定版式、插图、字体、导航和标准化文件名处理；依赖的 Python、lxml、Pillow 已在 Sigil 发行链路中出现 | 当前 CLI 面向批处理目录，使用人类可读 stdout，单本失败不保证非零退出；会自行决定输出目录与重名目录；代码源自 KFX Input/kfxlib，发行前必须补齐许可证全文、来源和修改记录 | **首版转换语义基线**；只引入经审计的核心与新建的受控 worker，不直接调用现有 CLI |
| `boko` Rust，提交 `b148716498fdac70134555293a7405913988256a` | 明确 GPL-3.0-or-later；原生、类型化错误、解析器测试和 fuzz 基础较好；可作为独立进程隔离 | 当前 KFX 导入器以单个 `CONT` 容器为模型，扩展名识别不含 `.kfx-zip`，不能直接覆盖现有六本 `.kfx-zip` 夹具；Rust 工具链会增加构建和发行复杂度 | 单容器差分测试与未来原生后端候选，不作为首版唯一后端 |
| `KFX2EPUB_csharp` | API 边界直观；支持解密后的 KFX-ZIP；输出 EPUB 3 | .NET Framework 4.8 不适合当前三平台内置发行；目录未见可独立确认的顶层许可证文件；仍有 illustrated-layout、KVG、PDF、JXR 等缺口 | 仅用于行为和测试对照，不进入构建或发行物 |

### 4.2 选型结论

首版采用“C++/Qt 编排层 + 独立 Python worker + 经审计的 KFX 转换核心”架构：

```text
菜单 / 拖放
    │
    ▼
KfxImportController
    │  创建任务、进度、取消、结果路由
    ▼
独立 worker 进程
    │  只读输入；JSON Lines 协议；写入私有临时目录
    ▼
临时 EPUB
    │
    ├─ 输出门禁：OCF/OPF/spine/资源/可加载性检查
    ├─ 原子移动到用户选择的另存为目标
    └─ 作为未保存文档在新 MainWindow 打开
```

采用独立进程而不是直接在 GUI 线程调用嵌入式 Python，原因是：

- KFX 属于不可信二进制输入，解析崩溃或内存异常不应直接终止主程序；
- 可在不强制中止主程序线程的情况下取消任务；
- stdout/stderr、退出码、资源限制和临时目录更容易形成稳定边界；
- 转换核心可以独立进行语料回归和后续替换。

现有 `convert_kfx2epub.py` 不作为产品接口。它的目录批处理、`archived_epub`、`dupnameN` 和 emoji 日志均不得泄漏到 Sigil 交互中。

### 4.3 许可证与来源前置门禁

开发前必须完成以下事项，否则不得把转换核心加入正式发行物：

1. 记录上游仓库、精确提交、文件清单和本项目修改；
2. 为 GPL v3 代码随发行物提供完整许可证文本和版权声明；
3. 审计 bundled `pypdf`、样式文件及其他第三方文件的许可证；
4. 确认所有引入代码与 Sigil-Enhanced 的 GPL-3.0-or-later 兼容；
5. 不把 `todo/vendor/kfx` 整目录作为构建输入，只复制明确列入 vendored source manifest 的必要文件；
6. 测试用商业书籍不得进入发布包、安装包或公开测试仓库。

## 5. 目标与非目标

### 5.1 产品目标

| ID | 目标 |
| --- | --- |
| G-01 | 从“增强”菜单把单个无 DRM KFX/KFX-ZIP 转换为 EPUB 3 |
| G-02 | 转换结果可另存为指定路径，且不替换、不修改当前窗口中的书 |
| G-03 | 转换结果可作为未保存的新 EPUB 文档在新窗口打开 |
| G-04 | 拖入 KFX 时明确提示，并可转换后在新窗口打开 |
| G-05 | 识别并拒绝 DRM 内容，不提供、不调用也不暗示解密能力 |
| G-06 | 转换失败不产生半成品目标文件，不改变源 KFX 和当前 EPUB |
| G-07 | 保存时默认不添加或更新 `Sigil version` 元数据 |
| G-08 | 未修改 EPUB 的同路径保存不重写文件，另存为/保存副本保持源文件字节一致 |
| G-09 | 转换和保存行为在 macOS、Windows、Linux 一致且可自动化回归 |

### 5.2 首版非目标

- 不解密 KFX，不集成 DeDRM，不接收密钥、账号、设备序列号或 Kindle 凭据；
- 不从 Kindle 应用、设备、云端或商店抓取图书；
- 不把 EPUB 转换回 KFX；
- 不支持 KPF、AZW、AZW3、MOBI、PDF 或普通 `.zip` 作为本入口的输入；
- 不在首版提供目录批量扫描；拖入多个明确的 KFX 文件可排队处理，但不递归扫描目录；
- 不自动执行 KFX 段落规范化、竖排转横排、多看适配、EPUB Structure Normalizer 或图片压缩；
- 不承诺与 Kindle 原渲染逐像素一致；
- 不在转换结果中保留 Kindle 专有交互、DRM 或无法合法转换的专有能力；
- 不把“未修改不变”扩大为“编辑后保存仍保持原 ZIP 字节布局”；只要内容发生实际编辑，必须正常导出新 EPUB。

## 6. 用户与核心场景

### 6.1 目标用户

- 拥有合法、无 DRM KFX 文件并希望转为 EPUB 编辑的用户；
- 编辑日文竖排轻小说、漫画或图文书的 EPUB 制作者；
- 希望在同一工具内完成转换、检查和编辑的维护者；
- 对 EPUB 重打包和编辑器自动元数据污染敏感的高级用户。

### 6.2 核心场景

| ID | 场景 | 成功结果 |
| --- | --- | --- |
| US-01 | 用户从增强菜单选择一个 `.kfx-zip` 并另存为 | 目标路径得到完整 EPUB，当前窗口内容不变 |
| US-02 | 用户从增强菜单转换并在新窗口打开 | 新窗口显示转换结果，文档没有绑定临时路径，首次保存弹出“另存为” |
| US-03 | 用户向窗口拖入一个 KFX | 弹窗说明 DRM 边界，默认按钮转换并在新窗口打开 |
| US-04 | 用户拖入多个 KFX | 一次确认后排队转换，每本成功结果各开一个新窗口，失败项单独报告 |
| US-05 | 用户选择了仍有 DRM 的 KFX | 转换立即失败并显示明确错误，不提供绕过建议，不留下 EPUB |
| US-06 | 用户取消转换 | worker 被终止，临时输出删除，源文件和当前书不变 |
| US-07 | 用户打开一本 EPUB 后不做修改直接保存 | 不调用导出器，不改文件内容、哈希或修改时间 |
| US-08 | 用户把未修改 EPUB 另存为新路径 | 新文件是源 EPUB 的字节级副本 |
| US-09 | 用户编辑 EPUB 后保存 | 正常导出编辑结果；默认仍不写 `Sigil version`，EPUB 3 的 `dcterms:modified` 按规范更新 |

## 7. 产品原则

1. **源文件只读**：转换器永远不原地修改、重命名或删除 KFX。
2. **先转临时文件，再交付**：用户目标路径只接收通过输出门禁的完整 EPUB。
3. **转换不是当前书编辑**：菜单转换不得污染当前 Book、撤销栈、检查点或修改状态。
4. **新窗口结果视为新文档**：临时 EPUB 只用于载入，不成为用户可见的当前文件路径。
5. **不处理 DRM**：只做检测和拒绝。
6. **默认保真**：不自动压图、不转换横竖排、不做阅读器私有适配。
7. **未修改即不导出**：保存操作不能因为“顺手补元数据”制造修改。
8. **失败可解释**：错误必须区分输入、DRM、转换、校验、磁盘和打开阶段。

## 8. 信息架构与交互

### 8.1 增强菜单入口

在“增强”菜单中新增：

```text
KFX 转换…
```

首版使用单一入口，不增加两个顶级菜单项。入口打开模态转换对话框，避免菜单膨胀，并让用户在同一处查看输入、输出方式、进度和警告。

没有要求默认快捷键，但动作必须注册到 `KeyboardShortcutManager`，允许用户自定义快捷键。

### 8.2 转换对话框

#### 初始状态

| 控件 | 文案/行为 |
| --- | --- |
| 输入文件 | 只接受单个 `.kfx` 或 `.kfx-zip`；提供“浏览…” |
| 输出名称 | 从 KFX 元数据生成 `[作者] 书名.epub`；预检前先使用源文件基本名 |
| 转换说明 | `仅支持无 DRM 的 KFX/KFX-ZIP。转换不会修改源文件。` |
| 选项 | 首版不暴露图片优化、目录重排、横竖排转换等高级选项 |
| 主按钮一 | `另存为 EPUB…` |
| 主按钮二 | `转换并在新窗口打开`，默认按钮 |
| 取消 | 转换前关闭对话框；转换中发起取消 |

用户点击“另存为 EPUB…”后先选择目标路径，再开始转换。若用户取消文件选择，不启动 worker。

#### 运行状态

- 显示当前阶段：`检查输入`、`解析容器`、`转换内容`、`生成 EPUB`、`验证 EPUB`、`保存结果`或`打开新窗口`；
- 只有后端能够提供真实比例时才显示百分比，否则使用不确定进度条；
- 显示经过时间，不显示未经测量的剩余时间；
- 禁用输入和两个主按钮；
- “取消”在最终原子替换目标文件的临界区短暂禁用；
- 详细日志默认折叠，面向用户显示结构化摘要，不直接展示 Python traceback。

#### 成功状态

另存为成功时显示：

- 最终路径；
- EPUB 版本、spine 项数、图片数、字体数；
- 警告数量；
- `在新窗口打开`和`在文件管理器中显示`操作。

新窗口打开成功后关闭转换对话框，并把警告摘要交给新窗口显示。警告不应把已成功加载的文档标记为“由用户编辑”。

### 8.3 拖放交互

拖放识别扩展名时不区分大小写，支持 `.kfx` 与复合扩展名 `.kfx-zip`。普通 `.zip` 不按 KFX 处理。

单文件提示：

```text
检测到 KFX 文件

是否将“文件名.kfx-zip”转换为 EPUB，并在新窗口打开？
仅支持无 DRM 的文件。源文件不会被修改。

[转换并打开] [另存为…] [取消]
```

要求：

- `转换并打开`为默认按钮；
- `另存为…`复用菜单的另存为流程；
- 不提供“直接加入当前书”；
- 不提供“以后不再询问”的静默转换选项；
- 拖入多个 KFX 时列出数量和文件名，用户确认后串行排队；
- 每个成功结果分别在新窗口打开；某一本失败不回滚其他已经成功打开的书；
- 批次摘要必须逐项显示成功、失败或取消；
- 混合拖入 KFX 与其他文件时，先将 KFX 子集交给本流程；用户处理完或取消后，其余文件继续走现有拖放逻辑，不得把 KFX 传给 `AddExisting`；
- 无论落点位于主窗口空白区、Book Browser 或编辑区域，只要拖放项中存在 KFX，都必须优先经过 KFX 分类器。

### 8.4 新窗口文档身份

转换后打开的新窗口必须满足：

- 使用产品内的多窗口机制，不启动一个依赖 shell 的外部命令；
- 窗口标题使用建议 EPUB 文件名并显示未保存状态；
- `m_CurrentFilePath` 或等价用户文档路径为空；
- 临时 EPUB 路径不进入“最近打开的文件”；
- 首次点击“保存”进入标准“另存为”对话框；
- 保存成功前关闭窗口会触发未保存确认；
- 临时源在 Book 完成加载后即可释放；若加载模型仍按需读取，则延迟到窗口关闭再清理；
- 打开失败时不创建空白新窗口，转换结果临时文件随任务清理。

## 9. 功能需求

### 9.1 FR-100 输入识别与预检

#### FR-101 支持的输入

- `.kfx`：无 DRM 的单容器 KFX；
- `.kfx-zip`：包含一个或多个 KFX 容器和关联资源的归档；
- 扩展名仅用于入口筛选，开始转换前必须检查文件签名和内部结构；
- 扩展名与内容不符时硬失败，不尝试按其他电子书格式猜测转换。

#### FR-102 文件预检

开始 worker 前必须检查：

- 路径是本地普通文件且可读；
- 文件在预检与任务打开之间没有被替换；
- 文件非空；
- 单容器具有预期 KFX/CONT 结构，归档具有 ZIP 签名；
- `.kfx-zip` 中不存在绝对路径、`..` 穿越、设备文件或符号链接逃逸；
- 归档项数量、单项大小、总解压大小和压缩比没有超过安全阈值；
- 临时目录和目标目录有合理的可用空间。

安全阈值必须集中配置并可测试，不得散落为多处魔法数字。超过阈值时显示“文件超出安全处理限制”，而不是“文件损坏”。

#### FR-103 DRM

- 识别容器 DRM scheme 和 `DRMION` 等已知加密标记；
- 一旦确认 DRM，返回专用错误 `KFX-E-DRM`；
- 不请求或保存解密凭据；
- 不尝试加载本机 Calibre、DeDRM 或 Kindle 组件；
- 错误文案只说明“此文件仍受 DRM 保护，Sigil-Enhanced 不提供解密功能”。

### 9.2 FR-200 转换能力

#### FR-201 必须保留的出版信息

首版必须尽可能保留：

- 标题、作者、语言、出版者、标识符和封面；
- spine 阅读顺序与 page progression direction；
- EPUB 3 Navigation Document；
- 有来源信息时生成兼容 NCX；
- 章节内链接、目录链接、landmarks、页码锚点和脚注引用；
- 日文竖排、Ruby、着重号、纵中横和常见 KFX 样式；
- 插图、封面、固定版式页、漫画 spread 信息；
- 可合法提取的内嵌字体及其引用；
- KFX 可表达且 EPUB 3 有标准承载方式的语义。

无法完整转换的能力必须产生警告，不得无提示地删除正文或主要图片。

#### FR-202 EPUB 输出约束

- 输出为 EPUB 3；
- `mimetype` 为首个 ZIP 项、内容正确且不压缩；
- `META-INF/container.xml`、OPF、manifest、spine 与 nav 可解析；
- 所有 spine 文档均在 manifest 中且可读取；
- 内部路径使用 `/`，不得包含路径穿越；
- 默认沿用 `kfx2epub` 已验证的日本书籍布局与样式处理，但不得宣称这是唯一标准目录结构；
- 默认不压缩、缩放、转码或降质原始图片；只有格式无法被 Sigil/EPUB 安全承载时才允许有损或替代转换，并必须产生警告；
- 不添加 `Sigil version` 元数据；
- 可以记录转换器自身的来源/版本到任务报告，但默认不把工具品牌写入 OPF；
- `dcterms:modified` 作为新生成 EPUB 3 的必要出版元数据写入一次，时间取转换提交时刻。

#### FR-203 输出门禁

worker 返回成功后，主程序必须在交付前执行：

1. 输出文件存在且非空；
2. OCF 基础结构检查；
3. 安全归档检查；
4. OPF、nav、NCX、XHTML 和 SVG 的基础 XML well-formed 检查；
5. manifest/spine/资源引用的关键一致性检查；
6. 使用 Sigil EPUB importer 做一次“可加载”预检，但不替换当前 Book；
7. 新窗口模式下实际建立新 Book 成功后，才向用户报告完成。

任何硬失败都不得通过“仍然保存半成品”绕过。非致命警告可随成功结果交付。

#### FR-204 输出命名

建议文件名按以下优先级生成：

1. `[首位作者] 标题.epub`；
2. `标题.epub`；
3. `源文件基本名.epub`；
4. `converted.epub`。

文件名必须清理平台非法字符、尾随点/空格和控制字符，但不擅自把正常 Unicode 转为 ASCII。重名时使用标准覆盖确认或由用户重新选择，不采用 `dupname1` 子目录规则。

### 9.3 FR-300 另存为 EPUB

- 用户选择目标路径后才启动转换；
- 输出始终先写到与最终目标同文件系统的随机临时文件；
- 通过门禁后使用原子 rename/replace 提交；
- 已存在目标文件时必须使用平台标准覆盖确认；
- 取消、失败或崩溃不得截断已有目标文件；
- 转换成功不改变当前窗口的 Book、文件路径、修改状态和撤销栈；
- 目标 EPUB 可被当前 Sigil-Enhanced 重新打开。

### 9.4 FR-400 转换并在新窗口打开

- 转换先写入应用私有临时目录；
- 使用新的 `MainWindow`/Book 实例加载；
- 不要求用户先保存；
- 成功加载后把该 Book 标记为“由转换创建、尚未保存”；
- 建议文件名与 KFX 元数据关联，但不得把临时路径当作保存路径；
- 当前窗口即使有未保存编辑也不弹出替换确认，因为其内容不被替换；
- 新窗口加载期间失败，当前窗口保持原样。

### 9.5 FR-500 任务、日志与错误

#### FR-501 Worker 协议

主程序与 worker 使用带版本的 JSON Lines 协议。最低事件集合：

```json
{"protocol":1,"event":"started","jobId":"..."}
{"protocol":1,"event":"phase","name":"parse","current":1,"total":6}
{"protocol":1,"event":"warning","code":"KFX-W-UNSUPPORTED","message":"..."}
{"protocol":1,"event":"result","status":"success","output":"...","summary":{}}
```

要求：

- stdout 只输出协议；调试日志写 stderr；
- 退出码必须与最终状态一致；
- 单本失败必须返回非零退出码；
- 协议解析失败视为 worker 失败；
- 用户文案由 C++/Qt 本地化层生成，不能依赖匹配英文异常字符串；
- Python traceback 仅进入可复制的技术详情，不作为主错误文案。

#### FR-502 错误分类

| 代码 | 类别 | 用户结果 |
| --- | --- | --- |
| `KFX-E-INPUT` | 文件不可读、类型不符或已被替换 | 不启动或中止任务 |
| `KFX-E-DRM` | 输入仍受 DRM 保护 | 明确拒绝，不生成输出 |
| `KFX-E-MALFORMED` | 容器、Ion、fragment 或归档损坏 | 显示损坏阶段和技术详情 |
| `KFX-E-UNSUPPORTED` | 书籍类型整体不受支持 | 不生成误导性 EPUB |
| `KFX-E-NOSPACE` | 临时或目标磁盘空间不足 | 清理临时文件，保留已有目标 |
| `KFX-E-CONVERT` | 转换核心失败 | 不交付半成品 |
| `KFX-E-VALIDATE` | 生成 EPUB 未通过输出门禁 | 保留诊断，不交付半成品 |
| `KFX-E-OPEN` | EPUB 已生成但新窗口加载失败 | 不交付转换结果；显示诊断并清理临时输出 |
| `KFX-E-CANCELLED` | 用户取消 | 安静结束并清理 |

#### FR-503 警告

至少对以下情况提供结构化警告：

- 不受支持的 KFX 交互或 illustrated-layout 分支；
- 无法转换的 JXR、KVG、PDF-backed 页面或媒体资源；
- 缺失、重复或冲突 fragment；
- 缺失字体、图片或导航目标；
- 样式属性降级；
- 元数据缺失并使用回退值；
- 固定版式或 spread 由启发式推断。

### 9.6 FR-600 未修改 EPUB 的保存与元数据策略

本节是全局保存行为，不只作用于 KFX 转换结果。

#### FR-601 `Sigil version` 默认策略

- 默认设置为“不写入 Sigil 版本元数据”；
- 保存时不得新增 `<meta name="Sigil version" ...>`；
- 对输入 EPUB 已有的 `Sigil version` 元数据，默认原样保留，不自动更新也不自动删除；
- 只有用户直接编辑/删除该元数据，或显式启用“保存时写入 Sigil 版本元数据”偏好后进行了实际内容修改，才允许改变它；
- 新安装与旧版本升级后的默认值均为关闭，不能因历史行为自动打开；
- 现有 `SIGIL_DISABLE_VERSION_META` 环境变量继续作为强制禁用兼容开关；默认行为不得再依赖用户设置该环境变量。

可在偏好设置中提供：

```text
[ ] 保存已修改的 EPUB 时写入 Sigil 版本元数据
```

该选项只在实际导出已修改/新建文档时生效，不得让未修改的普通“保存”失去 no-op 语义。

#### FR-602 修改日期策略

- EPUB 3 的 `dcterms:modified` 只在新建、转换或实际修改后导出时添加/更新；
- 未修改保存不得更新 `dcterms:modified`；
- EPUB 2 不为此目的添加 EPUB 3 元数据；
- 转换产生的新 EPUB 在生成时写入一次转换完成时间；在新窗口中未继续编辑而首次另存为时，不应仅因另存为再次更新时间。

#### FR-603 干净状态判定

只有同时满足下列条件，文档才可走未修改快路径：

1. 来源是一个已成功加载的本地 EPUB；
2. 所有编辑器缓冲区已提交检查，且没有内容变化；
3. Book、OPF、资源、元数据、导航、书签式内部编辑状态均未发生出版内容变更；
4. 导入器没有修复、重建、mend、补资源或转换 EPUB 版本；
5. 没有运行会写回的插件、自动化命令或规范化操作；
6. 源文件自打开后未被外部替换或修改；
7. 当前保存设置不要求执行用户明确选择的变换。

不得只依赖窗口标题上的 `[*]`。实现必须维护可测试的来源快照和 mutation ledger，区分：

- 用户编辑；
- 导入时修复；
- 插件/自动化写回；
- 仅 UI 状态变化；
- 仅分析或预览；
- 保存自身的元数据操作。

#### FR-604 保存行为矩阵

| 文档状态 | 操作 | 必须行为 |
| --- | --- | --- |
| 已加载 EPUB，干净，源未变 | 保存到原路径 | 直接成功并提示“没有需要保存的更改”；不调用 exporter，不写磁盘；SHA-256、大小、mtime 均不变 |
| 已加载 EPUB，干净，源未变 | 另存为 | 原 EPUB 到目标路径的字节级复制；目标哈希与源一致 |
| 已加载 EPUB，干净，源未变 | 保存副本 | 原 EPUB 到目标路径的字节级复制；当前路径不变 |
| 已加载 EPUB，存在实际修改 | 保存/另存为 | 正常导出；默认不写 `Sigil version`；EPUB 3 更新 `dcterms:modified` |
| 导入时发生自动修复 | 保存/另存为 | 视为已修改，正常导出；UI 必须明确显示修改状态或警告 |
| KFX 转换后新窗口 | 首次保存 | 以已生成且已验证的 EPUB 为基线另存为；不绑定临时路径，不写 `Sigil version` |
| 新建 EPUB | 保存 | 正常导出并写入规范所需元数据，不写 `Sigil version` |
| 源 EPUB 被外部改变 | 任意保存 | 禁止用旧快照覆盖；提示重新加载、另存为或取消 |

#### FR-605 快路径边界

- 保存前先同步当前编辑器缓冲区，再决定是否干净；
- “保存时清理/修复”设置不得在干净文档上静默运行；如用户显式要求运行，应先形成可见修改，再走正常导出；
- 字节复制使用安全、原子的目标写入方式，不经 EPUB importer/exporter；
- 同路径 no-op 必须避免触碰文件修改时间；
- 直接复制前再次核对源文件身份，避免 TOCTOU 覆盖；
- 若源文件不可再读取，不能伪装保存成功；
- 对无源文件的新文档和转换文档不使用“复制原始输入 KFX”快路径。

## 10. 非功能需求

### 10.1 性能与响应

- 输入预检和 worker 启动不得阻塞 GUI 线程；
- 超过 500 ms 的转换显示忙碌状态；
- 125 MB 级测试文件转换期间窗口仍可移动、重绘和取消；
- 多文件拖放默认串行转换，避免多个大型 Python 进程争抢内存；
- worker 应流式读取可流式处理的数据，避免无必要地同时保留输入、完整中间表示和多个 EPUB 副本；
- 取消请求在非原子提交阶段目标为 2 秒内结束 worker；若操作系统迟迟不退出，可升级为终止进程。

### 10.2 安全

- worker 不通过 shell 启动；所有参数使用参数数组传递；
- 使用随机、仅当前用户可访问的临时目录；
- 不信任归档内部文件名、声明大小、压缩比、Ion 长度或 fragment 偏移；
- 解析长度和偏移执行溢出检查；
- worker 不包含联网、自动下载依赖或执行归档内脚本的路径；
- 不把源文件名、标题、作者或异常上传到任何服务；
- 崩溃后的陈旧临时任务在下次启动时按年龄和所有权安全清理。

### 10.3 可用性与无障碍

- 所有控件可键盘操作并具有可访问名称；
- 默认按钮和破坏性覆盖按钮不得混淆；
- 进度和最终状态不仅依靠颜色区分；
- 错误摘要可选择和复制；
- 长路径和 Unicode 文件名完整显示，必要时中间省略但 tooltip 展示全路径；
- 所有用户文案进入 Qt 翻译体系，至少更新英文、简体中文和现有翻译模板。

### 10.4 可维护性

- UI、任务编排、worker 协议、转换核心、输出验证和保存快路径分层；
- KFX 核心不得直接依赖 `MainWindow`；
- worker 协议带版本，主程序拒绝不兼容版本；
- vendor 更新必须通过固定语料回归，不可直接替换目录；
- 记录转换核心版本到应用日志和诊断报告，但不默认写入 EPUB OPF。

模块职责：

| 模块 | 职责 |
| --- | --- |

| 文档状态层 | 保存原始 EPUB 身份、内容 mutation ledger 和保存快路径 |

## 12. 数据与状态模型

### 12.1 转换任务

```text
jobId
sourcePath
sourceIdentity { size, mtime, sha256 }
inputKind { kfx, kfxZip }
deliveryMode { saveAs, openNewWindow }
destinationPath?
suggestedFileName
state { queued, preflight, converting, validating, committing, opening, succeeded, failed, cancelled }
phaseProgress?
warnings[]
error?
tempRoot
tempEpubPath
```

状态只能单向推进。`succeeded`、`failed`、`cancelled` 为终态；已进入终态的 job 不能复用。

### 12.2 EPUB 来源快照

```text
sourceKind { epub, kfxConversion, newDocument, otherImport }
sourcePath?
sourceIdentity { size, mtime, sha256 }?
suggestedFileName?
publicationMutations[]
importerMutated
canByteCopy
```

关闭并重新打开文档后重新建立快照。检查点、UI 布局、标签页位置和分析结果不属于 publication mutation。

## 13. 验收标准

### 13.1 菜单与转换

| ID | 验收标准 |
| --- | --- |
| AC-01 | “增强”菜单存在 `KFX 转换…`，可由快捷键管理器发现 |
| AC-02 | 文件选择器只突出 `.kfx`、`.kfx-zip`，但仍对伪造扩展名做内容预检 |
| AC-03 | “另存为 EPUB…”成功生成可由 Sigil-Enhanced 重新打开的 EPUB 3 |
| AC-04 | 另存为转换不改变当前 Book 的路径、内容、修改状态和撤销栈 |
| AC-05 | “转换并在新窗口打开”创建独立窗口，首次保存进入另存为 |
| AC-06 | 新窗口不会把临时 EPUB 路径加入最近文件 |
| AC-07 | 输出文件名优先为 `[作者] 书名.epub`，Unicode 与平台非法字符处理正确 |
| AC-08 | 转换成功后可查看结构化警告和摘要 |

### 13.2 拖放

| ID | 验收标准 |
| --- | --- |
| AC-D01 | 向主窗口任意主要区域拖入 KFX 都出现转换提示 |
| AC-D02 | 默认按钮为“转换并打开”，取消后不创建任务 |
| AC-D03 | KFX 不会作为普通资源加入当前 EPUB |
| AC-D04 | 拖入多个 KFX 时串行处理并逐项报告 |
| AC-D05 | 混合拖放时 KFX 与其他文件按各自流程处理，KFX 不落入 `AddExisting` |

### 13.3 安全与失败

| ID | 验收标准 |
| --- | --- |
| AC-E01 | DRM fixture 返回 `KFX-E-DRM`，不生成 EPUB，不显示解密操作 |
| AC-E02 | 损坏 KFX/KFX-ZIP 不导致主进程崩溃 |
| AC-E03 | 路径穿越、超限归档和畸形长度被预检或 worker 安全拒绝 |
| AC-E04 | 转换、验证、打开任一阶段失败都不覆盖已有目标文件 |
| AC-E05 | 取消后源文件、当前书和已有目标文件不变，临时文件被清理 |
| AC-E06 | worker 不联网、不执行归档内脚本、不使用 shell 拼接命令 |

### 13.4 未修改保存

| ID | 验收标准 |
| --- | --- |
| AC-S01 | 打开不含 `Sigil version` 的有效 EPUB，不做修改后保存，OPF 仍不含该元数据 |
| AC-S02 | 同路径保存未修改 EPUB 前后 SHA-256、文件大小和 mtime 完全一致 |
| AC-S03 | 未修改 EPUB 另存为和保存副本后，目标 SHA-256 与源文件一致 |
| AC-S04 | 输入 EPUB 已有 `Sigil version` 时，默认保存不会更新或删除它 |
| AC-S05 | 未修改 EPUB 3 的 `dcterms:modified` 不变化 |
| AC-S06 | 实际编辑 EPUB 3 后保存会更新 `dcterms:modified`，但默认不添加 `Sigil version` |
| AC-S07 | 导入器发生 mend/修复时文档被明确标记为已修改，不错误进入字节复制快路径 |
| AC-S08 | 源 EPUB 被外部替换后，保存不会静默覆盖外部版本 |
| AC-S09 | KFX 转换新文档保存后不包含 `Sigil version`，并保持转换完成时的 `dcterms:modified`，除非用户又进行了实际编辑 |

## 14. 测试计划

### 14.1 KFX 语料

本地回归至少覆盖 `todo/vendor/kfx/test_file` 中现有六本 `.kfx-zip`：

4. C++ job 生命周期与取消测试；
5. 菜单和拖放 contract test；
6. 新窗口文档身份测试；
7. no-op 保存与字节复制测试；
8. EPUBCheck 与 Sigil 重开测试；
9. macOS、Windows、Linux 打包后 smoke test；
10. 代表性阅读器人工抽检，重点检查竖排、Ruby、彩插和固定版式。

## 15. 成功指标

首版发布门槛：

- 六本本地 KFX-ZIP 基线全部能完成转换并由 Sigil-Enhanced 打开，或对已书面确认的未支持书籍类型返回稳定、可解释的专用错误；
- 合成 DRM、损坏和恶意归档夹具均不导致主进程崩溃或目标文件损坏；
- 所有 no-op 保存夹具同路径保存前后 SHA-256 与 mtime 一致；
- 未修改另存为/保存副本夹具与源文件 SHA-256 一致；
- 默认路径下没有新增或更新 `Sigil version`；
- GUI 转换期间无持续主线程冻结；
- 三个平台的安装包包含所需 worker 与依赖，不要求用户另装 Python、Calibre、Kindle Previewer、.NET 或 Rust。

## 16. 分阶段实施建议

### Phase 0：来源、许可证与基线

### Phase 2：菜单、另存为与新窗口

## 17. 已裁决事项

1. 首版同时支持 `.kfx` 和 `.kfx-zip`，不接受只支持单容器的缩水实现。
2. 首版以 Python `kfx2epub` 的转换语义为基线，`boko` 用于差分验证和未来后端评估。
3. 不直接调用现有批处理 CLI，必须建立机器可读、可取消、退出码可靠的 worker。
4. 菜单使用一个 `KFX 转换…` 入口，对话框提供“另存为”和“新窗口打开”。
5. 拖放始终先提示，默认转换并在新窗口打开，不静默处理。
6. 新窗口中的转换结果是未保存新文档，不绑定临时路径。
7. 默认不写 `Sigil version`；已有该元数据默认保留不动。
8. 未修改保存采用 no-op/字节复制，而不是仅对导出器做“少写一个 meta”的局部修补。
9. DRM 检测后硬拒绝，不提供任何解密集成。
10. 图片优化、横竖排转换、多看适配和段落规范化均由用户后续显式执行。

## 18. 开发评审需确认但不改变产品边界的事项

以下事项允许在技术设计阶段选择具体实现，但不得降低上述验收标准：

- 三个平台如何定位并启动随包 Python worker；
- 归档项数、解压大小、压缩比和任务内存的具体安全阈值；
- 输出门禁复用现有 `ImportEPUB` 的方式，是只读 probe API 还是隔离 Book 加载；
- 新窗口 Book 完全载入后何时可安全删除临时 EPUB；
- mutation ledger 放在 `Book`、文档会话还是保存协调器；
- worker 取消时先发送协议取消还是直接终止进程，以及各阶段的宽限时间。

这些技术项完成后应形成独立设计文档，并回填本 PRD 的实现映射与测试编号。
